# 5. 不要浪费钱

本节口径是金钱：AI 相关的订阅、算力、API 与课程支出。每条写清一个月或一年实际花多少、换回什么。数字凡标 `（待核实：…）` 的都是占位，等抓取管线从厂商定价页回填，**不要当结论**；定价随时改，以官方文档当日版本为准。

### 1. 先把 API 用量按「哪个调用最贵」排出来，再决定省哪儿
<!-- 成本标签: 钱=0 时间=少 毅力=否 收益=中 口径=钱 -->
- 成本：0 元；十几分钟看账单
- 说人话：多数人的账单是一两个高频调用吃掉大头，而不是到处零散花钱。先按调用看花了多少，再动手；凭感觉关小参数、换便宜模型，常常省不下钱还把结果弄差。
- 收益：定位到集中支出后，单次优化的效果通常比全面紧缩大（待核实：需要给出「前 N 个调用占账单比例」的实测分布）（全国）
- 证据等级：C
- 来源：作者经验；具体用量看各家控制台账单页，本条不引第三方数字
- 备注：这条的收益量级只算「中」，因为省多少完全取决于你原来的浪费有多大——这正是本指南把性价比和证据等级分开标的原因。

### 2. 长对话、重复前缀的活，开提示缓存
<!-- 成本标签: 钱=0 时间=少 毅力=否 收益=大 口径=钱 适合=程序员|产品 -->
- 成本：0 元；改一次请求参数，几行代码
- 说人话：每次请求都把同一份长前缀重发一遍，等于同一段话付好几次钱。开缓存后，命中那部分的单价直接砍到一成——但前提是你的前缀够长，厂商设了起步线，短到不够长的根本不给缓存，所以反复带同一份长文档、长系统提示的活最划算，短问答收益为零。还有一个坑：缓存会过期，你要按你的请求间隔选档，不然写了缓存没读到，只付了写缓存的溢价。
- 收益：命中缓存的重复 token 单价按 Anthropic 文档为**基础输入价的 0.1 倍**（写缓存：5 分钟档 1.25 倍、1 小时档 2 倍；最短可缓存长度按模型 512 / 1024 / 2048 / 4096 token 不等；默认 5 分钟有效，每次命中免费续期）；OpenAI 为**默认开启**、复用 token 走折扣价**最高约 90%**（最短可缓存前缀其文档给出的一档是 1,024 可见输入 token，另两档写「随请求设置变化」）；Google Gemini 2.5 及更新模型**隐式缓存默认开启**、最短输入 2,048（2.5 Flash/Pro）到 4,096（3.5 Flash 等）token，具体折扣比例其定价页当日未列明（待核实：Gemini 的 cached-input 折扣率需在厂商定价页找到明确数字后回填）（全国）
- 证据等级：A
- 来源：只认厂商自己文档页的当日原文，三处均于 2026-09-20 抓取。① Anthropic《Prompt caching》<https://platform.claude.com/docs/en/build-with-claude/prompt-caching>，逐字：「5-minute cache write tokens are 1.25 times the base input tokens price」「1-hour cache write tokens are 2 times the base input tokens price」「Cache read tokens are 0.1 times the base input tokens price」「By default, the cache has a 5-minute lifetime. The cache is refreshed for no additional cost each time the cached content is used.」「the minimum cacheable prompt length is: 512 tokens … 1,024 tokens … 2,048 tokens … 4,096 tokens」；② OpenAI《Prompt caching》<https://platform.openai.com/docs/guides/prompt-caching>（实际渲染地址 developers.openai.com/api/docs/guides/prompt-caching），逐字：「Cheaper input tokens: Pay the model's reduced cached-input rate for reused tokens, discounted up to 90%」「Prompt caching is enabled by default for supported OpenAI models」「Cache-write pricing is not an additive fee」；③ Google《Context caching》<https://ai.google.dev/gemini-api/docs/caching>，逐字：「Implicit caching is enabled by default for all Gemini 2.5 and newer models」「We automatically pass on cost savings if your request hits caches」
- 备注：三家的口径不是一回事，别当成同一个数字：Anthropic 给的是**确定倍数**，OpenAI 给的是**上限**（「up to 90%」，不是每档都九折），Google 只说**默认返还节省**而当日页面没写比例。判定条件仍然优先于数字——请求间没有长且重复的前缀时收益为零，别为了开缓存改坏现有提示词结构。定价随时改，本页数字过期就得重抓，账号在不同平台（Bedrock / Vertex / Google Cloud）的可用性和价格也可能不同。

### 3. 别为「可能用得上」同时订多份全家桶
<!-- 成本标签: 钱=多 时间=少 毅力=是 收益=小 口径=钱 -->
- 成本：多份订阅叠加，每月数百元起；同时维护多套使用习惯要长期对抗惯性
- 说人话：不同产品的强项错开，但多数人 90% 的活落在一个工具上。同时订三份，省下的切换时间不值那份钱，还会因为每个都用不深而高估自己的产出。
- 收益：每份冗余订阅即每月纯支出（待核实：需要用量分布数据支撑「90% 落在一个工具」这句，目前是本指南作者观察，不足以外推）（全国）
- 证据等级：C
- 来源：作者判断，无直接文献
- 备注：反向也成立——只在一个生态里加深绑定有议价与安全成本，见第 17 节第 3 条（别把全部生产资料绑在一个账号或一家生态上）。
