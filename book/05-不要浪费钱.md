# 5. 不要浪费钱

本节口径是金钱：AI 相关的订阅、算力、API 与课程支出。每条写清一个月或一年实际花多少、换回什么。数字凡标 `（待核实：…）` 的都是占位，等抓取管线从厂商定价页回填，**不要当结论**；定价随时改，以官方文档当日版本为准。

### 1. 先把 API 用量按「哪个调用最贵」排出来，再决定省哪儿
<!-- 成本标签: 钱=0 时间=少 毅力=否 收益=中 口径=钱 -->
- 成本：0 元；十几分钟看账单
- 说人话：多数人的账单是一两个高频调用吃掉大头，而不是到处零散花钱。先按调用看花了多少，再动手；凭感觉关小参数、换便宜模型，常常省不下钱还把结果弄差。
- 收益：定位到集中支出后，单次优化的效果通常比全面紧缩大（待核实：需要给出「前 N 个调用占账单比例」的实测分布）（全国）
- 证据等级：C
- 来源：作者经验；具体用量看各家控制台账单页，本条不引第三方数字
- 备注：这条的收益量级只算「中」，因为省多少完全取决于你原来的浪费有多大——这正是本指南把性价比和证据等级分开标的原因。

### 2. 长对话、重复前缀的活，开提示缓存
<!-- 成本标签: 钱=0 时间=少 毅力=否 收益=大 口径=钱 -->
- 成本：0 元；有的厂商要自己加请求头或参数
- 说人话：每次请求都把同一份长前缀重发一遍，等于同一段话付好几次钱。开缓存之后重复那部分的单价大幅下调，反复带同一份长文档、长系统提示的活最明显；如果每次问题都不一样，开了也白开。
- 收益：命中缓存的重复 token 按折扣价计（待核实：各厂商折扣比例与最短可缓存长度须逐家从定价页抄，本条不留空口数字）（全国）
- 证据等级：A
- 来源：待回填。口径要求：只有厂商**自己定价页写明**的折扣比例才算 A 级，媒体转述和第三方博客不算；候选来源为各模型供应商 pricing / prompt caching 官方文档页
- 备注：判定条件写清楚：这条只在「请求间存在长且重复的前缀」时省钱，短问答场景收益为零；别为了开缓存改坏现有提示词结构。

### 3. 别为「可能用得上」同时订多份全家桶
<!-- 成本标签: 钱=多 时间=少 毅力=是 收益=小 口径=钱 -->
- 成本：多份订阅叠加，每月数百元起；同时维护多套使用习惯要长期对抗惯性
- 说人话：不同产品的强项错开，但多数人 90% 的活落在一个工具上。同时订三份，省下的切换时间不值那份钱，还会因为每个都用不深而高估自己的产出。
- 收益：每份冗余订阅即每月纯支出（待核实：需要用量分布数据支撑「90% 落在一个工具」这句，目前是本指南作者观察，不足以外推）（全国）
- 证据等级：C
- 来源：作者判断，无直接文献
- 备注：反向也成立——只在一个生态里加深绑定有议价与安全成本，见第 17 节第 1 条（别把全部生产资料绑在一个账号或一家生态上）。
